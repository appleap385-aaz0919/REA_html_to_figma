1. 실제 해석 HML 파일의 편집·저장: 표본이 없습니다.

## 브라우저 연결을 다시 해야 할 때

연결 설정은 `cms-knowledge/master-cms/agent-browser-session.json`, 연결 유지 도구는 `design-specs/revision-root-broker.py`입니다. 사용자는 현재 로그인된 Chrome 연결 유지를 선택했습니다. 마우스·키보드를 점유하지 않는 브라우저 제어를 우선하고 반복 승인 요청을 피합니다.

세션을 종료하면 PTY 프로세스, WebSocket, CDP 세션, Scripter iframe 연결은 만료될 수 있습니다. 저장된 ID는 과거 관찰값입니다. 현재 살아 있다고 가정하지 않습니다.

1. 현재 제공되는 목적별 도구와 연결 상태를 먼저 확인합니다. 기존 브로커가 살아 있으면 재사용합니다.
2. 새 브로커가 필요하면 승인 요청 사실을 먼저 알리고 **한 번** 연결합니다. 기존 스크립트를 사용할 때는 `python -X utf8 design-specs/revision-root-broker.py`를 유지 가능한 PTY(`tty=true`)로 실행합니다. 일반 파이프는 stdin이 닫혀 연결이 즉시 종료될 수 있습니다.
3. 승인 대기 시간은 180초입니다. 시간 초과 후 자동 재시도 루프를 만들지 말고 결과를 알립니다. 최신 연결 주소는 Chrome의 DevToolsActivePort와 대조할 수 있습니다. 임의로 Chrome을 종료하거나 로그인 상태를 초기화하지 않습니다.
4. Figma 문서 제목과 URL을 확인합니다. Scripter는 열려 있는 동안만 현재 iframe target을 찾아 연결합니다. hidden 속성이 있거나 크기가 0인 잔여 dialog는 열린 플러그인이 아닙니다.
5. 공개 Monaco API로 `file:///scripter.*` 모델에 작성한 코드를 넣고 실제 Run 버튼을 누릅니다. 입력 후 Run은 순차 실행합니다. 코드 래퍼는 `(/*SCRIPTER*/async function __scripter_script_main(){ ... })()/*SCRIPTER*/`입니다.
6. 완료 toast·플러그인 데이터·실제 캡처로 결과를 확인합니다. 호출을 보냈다는 사실만으로 완료를 판단하지 않습니다. 끝나면 보이는 Scripter를 닫고 focus emulation을 false로 돌립니다.

2026-11-12 마지막 작업에서는 연결과 실제 검증이 성공했고 Scripter를 닫았습니다. 사용자 클립보드는 사용하지 않았습니다. 이후 실행 환경에 제공된 브라우저 도구의 최신 지침을 우선합니다.

## 수정 스크립트 재실행 주의

현재 도면을 읽고 필요한 노드만 수정합니다. 전체 빌드 스크립트는 기존 도면과 사용자 코멘트를 덮어쓸 수 있습니다.

- `revision-aligned-plan.json`: 기본 화면별 최종 계획입니다.
- `revision-precise-overlay-plan.json`: 모달별 실제 변형·컨트롤 좌표 302개입니다.
- `revision-precise-overlays.js`: 정확한 컨트롤 좌표를 적용한 마지막 모달 렌더러입니다. 통합 buttons 배열로 푸터를 추정하던 예전 방식은 제거했습니다.
- `revision-resume-audit.js`: export 없이 실제 프레임 텍스트를 검사한 마지막 경량 검사입니다.
- `revision-final-alignment.js`: 일부 이동이 누적되는 작업을 포함하므로 그대로 반복 실행하면 안 됩니다.
- `revision-final-audit.js`: 이미지 export를 포함한 이전 검사입니다. 마지막 실행 전체가 완료된 것으로 간주하지 않습니다. 최신 검증 결과는 audit JSON의 finalVerification을 확인합니다.

Figma root pluginData의 `cmsRevisionNodes`는 화면 키와 실제 노드 ID를 연결합니다. `cmsRevisionAudit`는 누적 수정 수치이고, `cmsRevisionFinalVerification`은 2026-11-12 경량 검사의 실제 결과입니다. 페이지/컴포넌트의 `cmsRevision*` 태그를 이용해 기존 노드를 찾습니다.

- HML 편집기 저장, CMS 임시저장, CMS 전체반영을 구분합니다. HTML·HML·저장 OMR 및 문서 승인·검수 판정·Master 상태도 각각 따로 판단합니다. 쌍둥이 현재 관계와 생성 이력, 논리 세트와 쌍둥이 세트 수를 혼동하지 않습니다.
- 오래된 폼의 선행 메타 덮어쓰기, 같은 지문 쌍둥이 추가의 500과 비활성 탭에 숨은 오류, 미저장 HML 슬롯 전환의 입력 유실은 재현 기록입니다. 의도한 정책·근본 원인·수정 후 회귀 검증이 완료됐다는 뜻은 아닙니다.
- 사용자가 프로젝트 폴더명을 `Demo_36_REA_test`에서 `Demo_21_출제 마법사_v2_REA`로 직접 변경했습니다. 초기 research 문서 7개의 절대 링크 1,891곳을 현재 프로젝트 경로로 수정했습니다. 조사 내용과 근거 식별자는 유지했습니다. 다른 형식의 과거 자료에서도 이전 절대 경로가 나오면 현재 저장소의 동일한 상대 경로와 최신 근거 색인으로 대응 파일을 찾습니다.
- 실제 해석 HML·정상 Definition 세트 ZIP 표본은 현재 없다는 사용자 답변이 이미 완료됐습니다. 이를 사용자 응답 대기로 되돌리지 않습니다. 역할별 차이·일부 오류·서버 내부 규칙과 Service CMS의 수신·채점은 별도 미검증 범위로 유지합니다.

이번 정독 중 브라우저 연결·화면 조작·CMS 서버 쓰기·Figma 변경은 없었습니다. 저장된 연결 ID는 여전히 과거 관찰값이므로 실제 화면 작업을 요청받으면 현재 연결과 대상을 새로 관찰합니다.


## 2026-11-12: HML 50문항 초과 평가지 등록 제한 반영

사용자 첨부 요청을 기존 Master CMS 스토리보드에 반영했습니다. [변경 예정 부분 화면](https://www.figma.com/design/xCjdhdFkSbToMiRVlXVN2V/?node-id=13-2)을 초안 검수 섹션에 추가하고 신규 등록·초안 검수·승인 결과 3개 화면의 설명 4개를 수정했습니다. 실제 CMS에는 앞으로 반영될 정책이며 이번 작업에서 CMS 서버 데이터는 변경하지 않았습니다.

- 한 HML 파일의 문항 수가 **50을 초과하면** 평가지 등록여부를 미등록(N)으로 선택하고 제어를 비활성화합니다. `* 50문항이 넘는 HML은 평가지로 등록할 수 없습니다.`를 표시합니다.
- HML 업로드·문항 등록은 허용합니다. 기존 검수 조건을 충족하면 HML 승인도 진행하되 평가지 생성은 제한합니다. 서버 제한은 구현 요구사항이며 현재 실행 검증 결과가 아닙니다.
- 기존 초과 평가지 **31개**는 사용자 첨부에 기록된 건수입니다. DB를 재조회하거나 정리 작업을 실행하지 않았습니다. 정리 범위는 평가지 정보이며 원본 HML과 문항은 유지합니다. HML 문서 전체 폐기 기능으로 처리하지 않습니다.
- 요청 첫 문장에는 ‘50문항 이상’, 상세 지시와 안내에는 ‘50문항 초과’가 혼재합니다. 상세 지시를 기준으로 51문항부터 제한하는 설계를 반영했으며 **정확히 50문항의 기준**은 구현 전에 확인해야 합니다. 세트 자식 포함과 삭제·실패 문항 제외 여부도 요청에서 확정되지 않았습니다.

정책 원본과 근거는 `design-specs/hml-paper-limit-policy.json`, 검증은 `design-specs/hml-paper-limit-verification.json`에 있습니다. 실제 Figma 공개 플러그인 API로 변경 3개 화면과 신규 부분 화면을 읽어 텍스트 프레임 이탈·겹침·문자 깨짐이 모두 0건임을 확인하고 화면 캡처를 검토했습니다. 최신 delivery JSON에도 이번 변경을 연결했습니다. Figma Scripter는 닫고 브라우저 연결을 종료했습니다.


## 2026-11-12: 사용자 요청에 따른 로컬 커밋

이번 세션의 폴더명 변경에 따른 조사 문서 링크 수정, Markdown 정독 기록, HML 50문항 초과 정책의 Figma 반영 자료와 검증 근거를 함께 커밋합니다. `scripts/snapshot_history.py`로 조사 이력 색인을 갱신하고 스테이징 후 `scripts/snapshot_history.py --manifest`로 파일 목록과 SHA-256을 생성합니다. CMS 구현·기존 평가지 정리는 미실행 상태로 유지하며 원격 업로드는 요청되지 않았습니다.
