# Master CMS 로컬 목업

**`index.html`을 더블클릭하면 실행됩니다.** `열기.cmd`로도 열 수 있습니다. 백엔드·개발 서버·빌드·패키지 설치·인터넷 연결이 필요하지 않습니다. Chrome에서 검수했으며 Chromium 기반 브라우저를 권장합니다.

이 폴더 전체를 함께 보관하세요. `index.html`만 다른 위치로 옮기면 CSS와 JavaScript를 찾을 수 없습니다.

**수정 요청을 자동으로 연결하려면 `검수 연결.cmd`를 실행하세요.** Orca 안의 목업에서 영역을 표시하고 요청을 등록하면 현재 대화의 제가 HTML을 수정하고 결과를 패널로 돌려드립니다. 사용자가 확인 완료를 누르면 Figma·관련 정책 반영을 이어갑니다. [사용법과 롤백](REVIEW_TOOL.md)을 확인하세요. 일반 HTML 파일은 종전처럼 오프라인으로 볼 수 있고, 자동 전달은 Orca에 연결된 화면에서 사용합니다.


**원본과 비교하려면 [`화면_대조.html`](화면_대조.html)을 여세요.** 30개 화면의 원본·수정 목업 캡처를 나란히 볼 수 있습니다. 수정 내용과 남는 차이는 [`FIDELITY_REPORT.md`](FIDELITY_REPORT.md)에 기록했습니다. [OMR 편집 카드 대조](OMR_유형_대조.html)와 [OMR 미리보기 팝업 대조](OMR_미리보기_대조.html)에서는 유형별 편집 카드를 같은 너비로 볼 수 있습니다. 단원 트리는 패널 오른쪽의 «/» 버튼으로 접고 다시 엽니다.

## 어떤 화면인가요?

기존 Master CMS의 파란색 왼쪽 메뉴, 검색 조건, 목록 표, HTML/HML 병렬 상세, 네 개 수정 탭과 모달 구조를 기준으로 만든 목업입니다. 사용자 요청에 따라 임의의 예시 데이터만 사용하며 실제 CMS에 연결하지 않습니다.

| 메뉴 | 구현한 작업 |
|---|---|
| 홈·공통 | 메뉴 이동, 접속 표시, 로그아웃 확인과 예시 로그인, 처리 안내 |
| 전체 문항 | 분류·단원·키워드·난이도·형태·상태·기간 검색, 표시 개수와 페이지, 단건·공유 지문·세트 상세, 이전·다음, 상태 수정과 세트 일괄 처리 |
| 문항 수정 | 메타정보·HML·HTML·OMR 네 탭, 썸네일 등록·삭제, 단원·성취기준·내용영역·교과역량·행동영역 검색·추가·해제, 임시본 선택, 임시저장·전체 반영·취소 |
| 문항 관계 | 현재 출처·출처 추가 탭, 페이지와 용도 수정, 최소 출처 유지, 연결 평가지 조회, 배포 대상·재배포 안내 |
| HML 등록 | 파일 선택·드롭·제거, 예시 파일, 출처 조회·단원 조회와 자동완성, 필수값 검사, 단건·세트 예시 변환, S/F/D 검수, W·전체 D·평가지 미선택 승인 검사, 폐기 사유와 승인 확인, 처리 상태별 조회 |
| 디피니션 등록 | ZIP 등록과 단건 예시 변환, 50MB 제한, 출처·단원·페이지·용도, 검수·승인·폐기, 처리 상태별 조회. 평가지 등록 선택은 제공하지 않음 |
| 쌍둥이 | 그룹 목록·단일/세트 상세, 현재 쌍둥이·후보 검색 탭, 자기 자신·이미 연결됨·폐기·다른 유형 차단, 관계 추가·병합·해제, COPY/AI 모의 생성과 진행·생성 이력 |
| 평가지 | 검색·상세·포함 문항·배포 대상, 이름·상태·페이지·용도 수정, 후보 추가, 세트 단위 드래그 및 위/아래 이동, 그룹 제외·최소 한 그룹 유지, 저장 버전·취소·폐기 잠금 |
| 출처 관리 | 검색·등록·상세·수정, 연동 분류·교재·판형, 코드·이름 생성, 중복 조합 검사, 사용 여부와 매핑 수 구분, 미사용 전환 영향 확인 |
| 랩 | 수식 입력·기본 MathML 미리보기·키보드/필기 입력 영역·행렬, 14유형 OMR·JSON·비활성 비교, JSON 복원, 값 형식·드롭다운 참조, 기존/iframe 편집기 독립 상태·API 비교, 관리자 도구 모의 처리 |

원래 스토리보드 **30개 기본 화면과 52개 모달·팝업**의 대응표는 `coverage.json`에 있습니다. 목업 안의 **목업 안내·화면 구현 목록**에서도 원래 요소·정책·화면 변형 목록을 열어 볼 수 있습니다. 이 개수는 모든 화면 변형의 픽셀 일치나 모든 입력 조합의 검증 완료를 의미하지 않습니다.

## 바로 확인할 예시

- **전체 문항 → 2100002 → 문항 수정**: 임시본과 검수완료본을 선택합니다. 임시저장과 전체 반영의 차이를 확인할 수 있습니다.
- **전체 문항 → 2100007**: 공유 지문을 가진 4문항 세트를 확인합니다.
- **HML 문항 등록 → 6001**: 단건·세트 검수와 평가지 미선택 안내를 확인합니다.
- **HML 문항 등록 → 6002**: 51문항 HML의 평가지 미등록·비활성 정책을 확인합니다. HML 승인은 가능합니다.
- **평가지 관리 → 5001 → 수정**: 4문항 세트를 하나의 그룹으로 이동·제외합니다. 마지막 그룹의 제외는 차단됩니다.
- **평가지 관리 → 초과 평가지 정리 안내**: 예시 64문항 평가지 정보만 폐기합니다. 원본 HML과 Master 문항은 유지됩니다. 실제 31개 자료를 처리하는 기능이 아닙니다.
- **랩 → OMR 전체 유형**: 14유형을 펼쳐 정답 설정과 예시 응답을 확인합니다.

## 데이터 저장과 초기화

변경은 브라우저 `localStorage`의 `master-cms-offline-mock-v1`에 저장됩니다. 파일 경로 또는 브라우저가 달라지면 별도 저장 영역이 될 수 있습니다. 브라우저가 파일 저장을 막으면 현재 탭에서만 동작하며 안내를 표시합니다.

**목업 안내 → 데이터 내보내기/가져오기**로 브라우저 사이에 예시 데이터를 옮길 수 있습니다. **예시 데이터 초기화**는 이 목업의 데이터만 되돌립니다. 실제 조사 기록이나 CMS 데이터에는 영향을 주지 않습니다.

다른 탭의 저장 변경은 읽기 화면에 반영됩니다. 편집 중에는 현재 입력을 유지하고 오래된 저장을 차단합니다. 충돌 안내에서 현재 입력을 별도 파일로 내보내거나 최신 데이터를 다시 불러올 수 있습니다. 미저장 입력 내보내기는 복구 참고용이며 전체 데이터 가져오기 파일과는 형식이 다릅니다.

## 실제 CMS와 구분할 부분

- 실제 HML/ZIP 파서를 포함하지 않습니다. 선택한 파일의 바이너리를 변환하지 않으며 지정한 예시 문항 수로 결과를 만듭니다. 큰 문서는 최대 12개 대표 문항을 표시하고 전체 문항 수를 별도로 유지합니다.
- 디피니션의 정상 세트 ZIP 규격은 미확정이므로 신규 ZIP 등록은 단건 예시만 제공합니다.
- 별도 한글 편집기는 텍스트를 편집합니다. 벤더 HML 엔진의 레이아웃·해석 파일 저장을 재현하지 않습니다. 다운로드 파일도 예시이며 실제 원본 바이너리가 아닙니다.
- AI 추천·쌍둥이 AI 생성은 로컬 모의 처리입니다. 배포·캐시 reload·역할별 로그아웃은 실제 서비스에 요청하지 않습니다.
- OMR 14유형 편집 카드·검증·직렬화/복원과 HTML 편집/뷰어는 조사 때 보존한 원본 코드를 실행합니다. 파일 출처는 vendor/provenance.json에 있습니다. OMR 미리보기는 원본 서비스의 표·답란·수식 키패드를 로컬 iframe에서 실행합니다. 메시지 전송과 채점만 로컬 어댑터이며 서비스 수식 판정 엔진과 필기 인식은 포함하지 않습니다.
- 원본 HTML 편집기의 수식 팝오버는 번들에 포함된 MathLive/KaTeX를 사용합니다. 랩 수식 데모와 OMR Σ 팝업은 부분 MathML 구현입니다. 필기 인식은 연결하지 않았습니다. 외부 이미지 URL은 인터넷이 필요할 수 있으므로 오프라인 예시는 이미지 업로드를 사용하세요.
- 조사에서 발견한 입력 유실·숨은 서버 오류·오래된 폼의 덮어쓰기는 의도적으로 재현하지 않습니다. 목업은 입력 보존과 탭 충돌 안내를 제공합니다.
- ‘50문항 이상/초과’가 혼재한 요청은 **초과(51문항부터)**를 기준으로 반영했습니다. 정확히 50문항과 세트·실패·삭제 문항의 산정 기준은 실제 구현 전에 확정해야 합니다.

## 검수 자료

- `verification/report.json`: 실제 파일 실행, 화면 진입과 기능별 브라우저 검사 결과입니다.
- `verification/bughunt/report.json`: 고정 시드·사용자 행동별 반복 검수 결과입니다.
- `verification/bughunt/manifest.json`: 검수한 파일 해시, 브라우저와 시드·관측 범위입니다.
- `verification/*.png`: 검토용 실제 실행 화면입니다. `failure-*`와 하위 실패 묶음은 수정 전 재현 자료입니다.
- `QA_REPORT.md`: 조사 기록과의 대조, 발견·수정한 문제, 검증 결과와 남은 한계입니다.

HTML 열람에는 Python이나 Node가 필요하지 않습니다. 자동 요청 연결에는 설치된 Python과 Orca CLI가 필요합니다. 개발자가 검수를 다시 실행할 때만 설치된 Python Playwright와 Chrome을 사용합니다.

```powershell
python -X utf8 -u master-cms-mockup/verify_mockup.py
python -X utf8 -u master-cms-mockup/verify_review_v2.py
python -X utf8 -u master-cms-mockup/verify_review_v3.py
python -X utf8 -u master-cms-mockup/bughunt_mockup.py
```


원본 편집기 재검수는 `python -X utf8 -u master-cms-mockup/audit_native_editors.py`, 카드별 비교 캡처는 `python -X utf8 -u master-cms-mockup/capture_omr_reference.py`로 다시 실행할 수 있습니다. 프로젝트 루트에서 실행하며, 검수에만 로컬 Python Playwright와 Chrome이 필요합니다. 목업을 여는 데는 필요하지 않습니다.


미리보기 검수는 `python -X utf8 -u master-cms-mockup/audit_preview.py`로 실행합니다. 이 검수만 원본 대조용 개발계 미리보기를 인터넷으로 열며, 원본 서버에 문서를 저장하거나 채점을 요청하지 않습니다. 목업 자체는 오프라인으로 동작합니다. 재빌드는 `build_preview_runtime.py`로 수행하며 빌드할 때만 esbuild가 필요합니다.

일반 Chrome·Edge에서도 화면 검수 요청을 자동 전달할 수 있습니다. `검수 연결.cmd`를 실행하고 HTML의 **작업 폴더 연결**에서 프로젝트의 `review-work` 폴더를 최초 한 번 선택합니다. 상세 절차는 [REVIEW_TOOL.md](REVIEW_TOOL.md)를 확인하세요.

검수 패널의 **Description** 탭은 현재 화면의 실제 Figma 설명과 같은 번호를 표시합니다. 번호를 누르면 설명과 화면 위치를 함께 확인할 수 있습니다. 화면·편집 탭·지원되는 팝업을 바꾸면 해당 설명으로 전환하며, 현재 조건에서 없는 요소는 설명에 안내합니다. 문항 상세의 상태 정보는 기존 08번을 유지합니다.

Figma 반영 완료 작업에서 설명을 다시 내보내면 정적 HTML과 연결 폴더의 설명 데이터가 함께 갱신됩니다. 작업 폴더가 연결된 HTML은 설명을 자동 반영합니다. 연결하지 않은 경우 HTML을 새로고침하면 갱신된 정적 설명을 읽습니다. Figma를 수동 수정한 경우에도 내보내기·게시가 필요합니다. 자세한 반영 절차는 `../review-work/AGENT_WORKFLOW.md`를 따릅니다.

Description 검수는 `verify_descriptions.py`, 설명 게시·연결 검수는 `verify_description_sync.py`로 실행합니다. 후자는 DirectoryHandle 테스트 어댑터를 사용하며 새 네이티브 폴더 권한 창을 검수했다는 의미는 아닙니다.
