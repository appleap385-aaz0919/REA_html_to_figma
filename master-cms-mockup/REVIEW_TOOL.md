# 화면 수정 요청

일반 Chrome·Edge에서 `index.html`을 열어 사용합니다. 웹 서버는 필요 없습니다. HTML 수정과 사용자 확인 후 Figma·정책 반영은 현재 대화의 에이전트가 수행합니다.

## 처음 연결하기

1. HTML을 새로고침합니다. 2026-11-19 사용자가 삭제를 요청한 이전 검수 기록은 이때 초기화됩니다. CMS 예시 데이터는 유지합니다.
2. `master-cms-mockup/검수 연결.cmd`를 실행합니다. Python·Orca CLI와 현재 프로젝트의 기존 Codex 대화가 필요합니다. Orca 내부 브라우저를 열지 않습니다.
3. HTML의 **화면 검수 → 작업 폴더 연결**을 누르고 프로젝트의 **review-work** 폴더를 선택합니다. 폴더 권한 창은 브라우저 보안 절차입니다. 파일 수정 허용을 묻는 경우 허용합니다. 이 폴더 외의 시스템·임시 폴더를 선택하지 않습니다.
4. **작업 연결됨**을 확인합니다. 같은 탭을 새로고침하면 저장한 폴더 권한으로 재연결합니다. 브라우저가 권한을 해제하면 다시 연결합니다. 다른 창으로 연결을 옮기려면 그 창에서 버튼을 눌러 선택합니다.

화면 보기만 할 때는 Python·Orca·폴더 권한이 필요 없습니다. 파일 전달 기능은 Chrome·Edge의 File System Access API를 사용합니다. 이 연결은 선택한 폴더 안의 JSON 파일을 주고받으며 서버 포트를 열지 않습니다.

## 요청과 확인

1. 원하는 화면·팝업에서 **펜으로 표시**를 누르고 영역을 드래그합니다. 펜을 켜면 CMS 입력을 잠그고, 끄거나 Esc를 누르면 다시 사용할 수 있습니다.
2. 수정할 내용과 변경 구분을 입력하고 **요청 등록**을 누릅니다. 변경 구분은 **화면·배치 수정**, **기능 수정**, **오류 수정**을 동시에 선택할 수 있습니다. **정책 수정**은 선택 항목에서 제외했습니다. 정책 영향은 에이전트가 실제 수정 내용을 보고 판단합니다.
3. 요청은 **전달 대기 → 요청 전달됨 → 수정 중 → 확인해 주세요**로 진행합니다. 구현 전 확인이 필요하면 **답변 대기**로 바뀝니다. 패널의 질문에 답변하면 같은 요청에서 작업을 이어가며, 질문과 답변은 요청 카드 본문에 계속 표시합니다. 전달 접수는 작업 완료를 뜻하지 않습니다. 에이전트가 실제 수정과 검수를 수행한 뒤 결과를 기록합니다.
4. 정책이 실제로 바뀐 경우에만 작업 결과에 **변경된 정책**을 함께 표시합니다. 이전 기준·변경 기준·적용 조건을 설명하며, 정책 문서는 사용자 확인 후 반영합니다. 정책 변경이 없으면 정책 내용과 정책 상태 행을 표시하지 않습니다.
5. 수정 결과가 도착하면 **수정본이 준비되었습니다** 안내와 **새로고침** 버튼이 나타납니다. 안내는 패널을 닫아도 유지되며 자동으로 페이지를 바꾸지 않습니다. 코드 변경을 불러오는 전체 새로고침 후에도 패널 열림·펼친 요청·상세 기록·패널 스크롤·미전송 입력을 복원합니다. 저장하지 않은 CMS 입력이 있으면 기존 이탈 확인을 거칩니다. 상태 정보의 저장 확인 후에는 서비스 화면만 갱신하고 검수 패널 DOM과 작성 내용을 유지합니다. 화면 이동으로 패널이 닫히지 않으며 닫기 버튼으로 직접 닫은 상태도 기억합니다. **확인 완료**는 사용자가 누릅니다. 아직 다르면 **수정이 더 필요해요**로 같은 요청을 이어갑니다.
6. 확인 후 별도 작업으로 Figma와 관련 정책·기록에 반영합니다. 실제 반영 근거가 없는 항목은 대기로 유지합니다.

## 영역과 화면 기록

**위치·기록 보기 → 영역 다시 그리기**는 기존 영역을 지우고 즉시 같은 요청의 새 영역을 그리게 합니다. 요청 번호·내용·최초 화면 기록은 유지합니다. Esc로 중단하면 영역 없이 요청을 유지하며, 다시 같은 버튼으로 지정할 수 있습니다. 새 요청은 상단 펜으로 그립니다.

**화면 기록 보기**에서 이미지를 누르면 HTML 안에서 확대합니다. 닫기나 Esc로 돌아옵니다. 수정 후 이미지가 기록되지 않았다면 빈 비교 칸을 보여주지 않습니다. 자동 기록은 일부 iframe·수식 등의 실제 모습을 모두 담지는 못합니다. 화면 이미지 보완·파일 첨부 입력은 삭제했습니다. 사용자가 캡처를 관리할 필요는 없습니다. 에이전트가 결과를 기록할 때 필요한 수정 후 캡처를 첨부합니다.

이미 전달한 추가·재수정 요청은 카드 본문에 표시하며 입력란은 비웁니다. 이전 버전에서 전송 후 남은 중복 내용은 본문 이력을 유지하면서 입력란에서 정리합니다.

요청 초안과 보충 설명은 `master-cms-visual-review-v2`에 저장합니다. 패널 보기 상태는 같은 탭의 sessionStorage `master-cms-review-view-v1`에 별도로 저장합니다. 다른 탭의 변경이나 저장 용량 오류는 안내합니다. **기록 보관·기타**의 JSON 내보내기·가져오기는 별도 보관이 필요할 때만 사용합니다. 같은 ID의 다른 이력을 임의로 덮어쓰지 않습니다.

## 연결 프로그램

`review_agent.py`의 기본 `launch`는 외부 HTML의 폴더 연결 모드입니다. 기존 Orca 화면 방식은 명시적으로 `--mode orca`를 지정할 때만 사용합니다. 새 AI 에이전트는 실행하지 않으며, 현재 프로젝트의 기존 대화로 요청을 전달합니다. 매 전송 시 현재 터미널 핸들을 새로 조회합니다. 전달 여부가 불명확하면 중복으로 보내지 않습니다.

요청은 `review-work/jobs/`, 결과는 `review-work/updates/`에 기록합니다. 브라우저가 결과를 저장했다고 확인한 다음에만 결과 파일을 `.applied`로 바꿉니다. 재수정 전 토큰의 결과는 적용하지 않습니다. 브라우저와 연결 프로그램의 교환 파일은 `runtime-browser/`입니다. 실제 작업 지침은 `../review-work/AGENT_WORKFLOW.md`입니다.

연결을 종료하려면 프로젝트 루트에서 실행합니다.

```powershell
python -X utf8 master-cms-mockup/review_agent.py stop
```

## 롤백과 검수

이번 변경 직전 코드와 관련 문서 839개는 `../rollback/before-external-html-review-20261119/`에 보존했습니다. 연결 프로그램을 종료하고 `restore.py --check`로 검사한 뒤 `--apply`로 복원합니다. 현재 파일은 displaced 폴더로 보존합니다. 브라우저 기록 삭제와 사용자가 삭제를 요청한 jobs/updates는 코드 백업 복원과 별개입니다.

`verification/review-v3/report.json`은 삭제·확대·다시 그리기·작은 화면 검수입니다. `file-bridge-report.json`은 일반 Chrome의 실제 폴더 선택 권한·실제 파일 요청/시작/결과·새로고침·사용자 승인 후 문서 작업을 검사합니다. 테스트의 대화 전송만 대역이며 실제 사용자 대화에 테스트 요청을 보내지 않았습니다. 실제 새 요청의 대화 도착은 사용자가 연결해 등록한 뒤 확인합니다. 이전 11개 흐름 검사와 원본 CMS 대조는 각 보고서의 날짜·범위를 따릅니다.

파일 갱신 중 브라우저의 읽기 스냅샷이 만료되면 새 파일 핸들로 다시 읽습니다. 일시적인 파일 교체는 영문 경고로 표시하지 않으며 다음 주기에도 복구를 시도합니다. 권한 거부·연결 장애는 한국어로 복구 방법을 안내합니다.


## 완료한 요청의 표기 확인

완료 목록에서도 현재 화면과 연결되는 요청의 번호와 영역을 표시합니다. ‘표시 숨김/보기’로 함께 제어할 수 있으며, 번호를 눌러도 완료 목록을 유지합니다. 완료 카드의 **표기 보기**는 현재 요소를 찾아 이동합니다. 요소가 사라졌거나 내용·팝업·탭이 달라졌으면 요청 당시 캡처에 빨간 영역과 번호를 표시해 엽니다. **수정 전 표기 보기**는 현재 요소가 남아 있어도 당시 화면을 직접 확인하는 버튼입니다.

과거 영역은 당시 캡처를 기준으로 표시하며 현재 화면의 정확한 위치로 추정해 덧씌우지 않습니다. 화면 크기가 달라지면 이미지와 영역을 같은 비율로 축소합니다. 영역 없는 화면 전체 요청은 캡처만 표시하고, 연결된 요소와 캡처가 모두 없으면 위치·기록 안내를 표시합니다. 열람 동작은 요청 완료·사용자 승인·Figma·정책 반영 상태나 이력을 변경하지 않습니다.

## 현재 화면의 Figma Description

**완료** 오른쪽의 **Description** 탭에서 현재 화면에 해당하는 Figma 설명을 읽습니다. 설명과 서비스 화면에는 같은 보라색 번호가 표시됩니다. 설명 제목을 누르면 해당 요소로 이동하고, 화면의 번호를 누르면 설명으로 이동합니다. **표시 숨김/보기**로 번호를 제어합니다. 요청 표시는 기존 빨간색을 사용하며 두 종류의 번호를 동시에 섞어 표시하지 않습니다.

화면·편집 탭·등록 문서의 상태·지원되는 팝업과 팝업 내부 탭에 따라 설명이 바뀝니다. OMR 미리보기의 프레임 내부에도 번호를 표시합니다. 현재 조건에 없는 요소와 아직 설명이 등록되지 않은 화면은 이유를 안내하며 위치를 추정해 표시하지 않습니다. 설명을 보는 동안 서비스 입력을 잠그지 않습니다. 작성 중인 요청은 진행 중 탭으로 돌아오면 계속 작성할 수 있습니다.

Figma 반영 완료 시 에이전트가 실제 설명을 다시 내보내고 같은 데이터에서 HTML 정적 파일과 작업 폴더의 JSON을 갱신합니다. 작업 폴더가 연결되어 있으면 설명은 페이지 새로고침 없이 갱신됩니다. 연결되지 않았으면 다음 새로고침 때 새 정적 설명을 읽습니다. **HTML 코드 자체를 수정한 경우에는 기존과 같이 새로고침이 필요**하며, 열린 패널·선택한 탭·스크롤은 복원합니다. Figma를 수동으로 수정한 경우에도 내보내기·게시 단계가 필요합니다.
