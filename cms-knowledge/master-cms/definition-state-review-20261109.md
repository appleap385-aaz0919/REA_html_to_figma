# Definition 상태와 ZIP 등록 검증 검토

작성일: 2026-11-09. **이 정적 검토의 증거 범위는 1826~1890입니다.** 개발 CMS의 교육과정 22 자료를 기준으로 정리했습니다. 검토 담당자는 로컬 파일만 읽고 이 보고서만 작성했습니다. 이후의 실제 ZIP 등록, QA 문서 661의 R/M 전환 및 승인 검증은 [phase28 기록](session-20261109-phase28.json)과 [QA 등록 기록](definition-qa-import-intent.json)을 우선 확인해야 합니다. 이 보고서에서 R/M 및 정상 등록이 미확인이라고 적힌 부분은 1890번 증거 시점의 한계입니다.

**근거의 구분**

- **실제 표시**는 이미 수집한 상세·폼의 DOM/접근성 결과를 뜻합니다. **실제 동작**은 입력·클릭 전후 결과가 연결된 경우에만 사용합니다. 이 증거의 `visibility: hidden`과 스크롤 기록은 픽셀 검사를 대신하지 않습니다. 스크롤 결과도 스스로 “DOM coverage is distinct from pixel inspection”이라고 구분합니다. [169 표시](evidence/1833-definition169-state.json#L53), [179 스크롤](evidence/1843-definition179-scroll.json#L53), [관찰기](sources/runtime/registration-page-observation.js#L1), [스크롤 수집기](sources/runtime/page-scroll-walk.js#L1)
- **소스 확인**은 저장된 HTML·JS의 선언과 분기만 확인한 경우입니다. 서버 내부 구현, 업로드 결과, 다운로드 파일 내용과 상태 전이는 해당 소스만으로 확정하지 않습니다. 현재 폼의 저장된 원본은 [1865 원본 증거](evidence/1865-definition-form-current-source.json#L53)와 [신규 등록 HTML](sources/definition-registration-form-current-20261109.html#L148)입니다.
- 상세 표본은 169·170·179·180·175·299·173·530입니다. 상태 집계와 파일명 정정에는 바로 앞 목록 근거 1830~1831을 보충했고, 추가 승인된 범위인 1869~1890의 등록 검증도 반영했습니다. [목록 결과](evidence/1830-definition-current-all-rows.json#L53), [상세 169](evidence/1833-definition169-state.json#L53), [상세 530](evidence/1861-definition530-state.json#L53)

**승인 상세의 버튼 동작은 소스에서 확인한 범위**

현재 승인 상세의 문항 상세 링크는 `/item/all/detail.donga?itemId=...`, `target="_blank"`, `rel="noopener"`입니다. 문항 수정 버튼은 먼저 `/item/all/draft-check.donga?itemId=...`를 조회하고, 임시본이 없으면 수정 페이지를 열며, 있으면 임시저장/검수완료 선택 모달을 여는 코드입니다. 선택에 따라 `draft=Y` 또는 `draft=N`을 붙이고, 새 탭이 열리지 않으면 같은 탭으로 이동합니다. 실패·리다이렉트는 “임시저장 확인에 실패했습니다.”로 처리합니다. **이번 상세 범위에서는 이 버튼을 눌러 각 분기를 실행한 증거가 없습니다.** [현재 173 원본의 링크·수정 스크립트](evidence/1858-definition173-source.json#L53), [현재 530 원본](evidence/1862-definition530-source.json#L53), [기존 530 원본의 읽기 쉬운 동일 계열 코드](sources/definition-approved-detail.html#L402)

다운로드는 공통 코드상 `/file/download.donga`에 원본 URL과 이름을 전달하고, 성공 시 blob을 저장하며, 리다이렉트는 로그인 이동, 실패는 토스트로 처리합니다. 현재 버튼이 존재한다는 것과 실제 파일을 받아 ZIP 내부를 검증했다는 것은 다릅니다. 특히 모의 W169/P170/F175의 다운로드 원본 경로는 저장 HTML에서 `.hml`인데 표시 파일명은 `.zip`입니다. 경로와 이름의 불일치만 확인했으며 파일 형식·손상 원인·다운로드 성공을 추정하지 않았습니다. **ZIP 등록 폼과 실제 검증**

**ZIP 등록의 소스 정책**

1. **파일을 선택하면 로컬 큐에 담습니다.** `autoProcessQueue=false`이고 초기 URL은 `#`입니다. .zip 확장자·파일 수·크기 검증은 Dropzone이 수행합니다. 확장자 비교는 파일명 끝부분을 소문자로 바꿔 비교하므로 대소문자를 구분하지 않는 코드입니다. ZIP 내부 구조 검사는 이 클라이언트 코드에 없습니다. 크기는 `size > 50 * 1024 * 1024`일 때 거부하므로 소스상 기준은 52,428,800B입니다. 경계값 자체와 대문자 .ZIP의 실제 선택 결과는 아직 없습니다. [폼 L678](sources/definition-registration-form-current-20261109.html#L678), [라이브러리 accept/isValidFile L26](sources/assets/dropzone-min-636df3a8e27015e39c86a5f61372c4e5.js#L26)
2. **등록 시작은 파일 검증 후 폼 검증을 거칩니다.** accepted 파일이 0개이면 이벤트를 중단하고 HML 경고를 냅니다. 파일이 있으면 `checkValidity()`를 확인합니다. 필수값이 빠지면 공통 코드가 제출을 막고 “미입력 정보가 있습니다.”와 `was-validated`를 적용합니다. 유효할 때만 accepted 파일을 QUEUED로 되돌리고 등록 버튼을 잠급니다. 현재 폼·공통 코드의 이 경로에는 최종 등록 확인 모달을 여는 분기가 없습니다. **모든 값이 유효한 제출은 이번 런타임에서 실행하지 않았습니다.** [폼 L754](sources/definition-registration-form-current-20261109.html#L754), [공통 L247](sources/assets/common-8dc66a9d95b497a50939a25f89dee707.js#L247)
3. **예정된 요청 순서는 업로드 주소 발급 → 파일 PUT → 생성 POST입니다.** 폼은 `/item/difi/upload-url.donga`에 hx-post합니다. `examUploadReady` 이벤트를 받으면 examDocumentId/filePath/원본파일명을 채우고 응답의 uploadUrl로 binary PUT을 보냅니다. Content-Type도 응답값을 그대로 사용합니다. Dropzone success 후 `/item/difi/create.donga`에 POST합니다. 이것은 프런트엔드의 연결 규약이며 발급·PUT·생성 응답이나 서버 트랜잭션 결과를 본 증거는 아닙니다. [폼 action L148](sources/definition-registration-form-current-20261109.html#L148), [create와 제출 L742](sources/definition-registration-form-current-20261109.html#L742), [발급 후 PUT·생성 L776](sources/definition-registration-form-current-20261109.html#L776)
4. **진행·실패·재시도 처리는 선언되어 있습니다.** sending 때 진행 막대를 보이고 complete 때 숨깁니다. error는 메시지 토스트를 띄우고, 파일 형식·크기로 미승인된 파일은 제거하며, 승인된 파일의 전송 실패는 버튼을 다시 활성화합니다. 재제출 전 QUEUED로 바꾸는 코드와 afterRequest에서 단계 연속 여부에 따라 버튼을 푸는 코드가 있습니다. 발급 실패·실제 PUT 실패·생성 실패·재시도 성공은 실행 증거가 없습니다. [QUEUED 재설정 L769](sources/definition-registration-form-current-20261109.html#L769), [진행·실패·버튼 L793](sources/definition-registration-form-current-20261109.html#L793), [진행 템플릿 L606](sources/definition-registration-form-current-20261109.html#L606)
5. **메타정보의 브라우저 제약은 제한적입니다.** 출처 required, 단원 required·maxlength20, 시작/끝 required·min1, 용도 required(C 공통/T 교사용), 등록자 disabled입니다. 단원 안내는 12/14/20자리이지만 해당 input에 pattern/minlength는 없고, 읽은 폼의 제출 코드와 common.js에는 단원 존재·허용 길이·시작≤끝의 별도 비교가 없습니다. 이는 서버의 수용 정책을 뜻하지 않습니다. [출처 L184](sources/definition-registration-form-current-20261109.html#L184), [단원·페이지·용도·등록자 L247](sources/definition-registration-form-current-20261109.html#L247), [제출 L755](sources/definition-registration-form-current-20261109.html#L755), [공통 검증 L247](sources/assets/common-8dc66a9d95b497a50939a25f89dee707.js#L247)

[자동완성 L695](sources/definition-registration-form-current-20261109.html#L695), [출처 조회 선언 L424](sources/definition-registration-form-current-20261109.html#L424), [선택 적용 L823](sources/definition-registration-form-current-20261109.html#L823)
7. **취소는 로컬 폼을 떠나는 확인입니다.** data-confirm-cancel 링크는 공통 캡처 핸들러가 가로채 확인 모달을 띄우고, 확인 시 원래 링크 클릭을 재개합니다. 이 코드에는 업로드 취소 API·객체 삭제 API·문서 폐기 요청이 없습니다. 브라우저 탭 닫기나 다른 메뉴 이탈까지 같은 보호가 적용된다고 일반화하지 않습니다. [취소 모달 L290](sources/definition-registration-form-current-20261109.html#L290), [공통 처리 L259](sources/assets/common-8dc66a9d95b497a50939a25f89dee707.js#L259)
8. **서버 확장자 재검사 주석은 구현 증명이 아닙니다.** “서버도 저장 때 경로 확장자를 같은 기준으로 다시 본다”는 주석은 있지만 이번 자료에는 서버 소스나 해당 반려 응답이 없습니다. 정책 의도와 서버 검증 실증을 분리합니다. [주석 L675](sources/definition-registration-form-current-20261109.html#L675)
