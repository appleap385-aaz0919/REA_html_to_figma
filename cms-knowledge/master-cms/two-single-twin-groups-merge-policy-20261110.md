# 두 단건 쌍둥이 그룹의 병합과 기준 관계 복원

작성일은 2026-11-10이며 범위는 phase66의 근거3105~3151입니다. 정상 UI로 두 단건 그룹 `{216,240}`과 `{239,246}`을 만든 뒤216에서239를 추가하자 네 문항 모두 같은 합집합4개로 조회됐습니다. 이후246만 해제해 기존 `{216,239,240}` 관계와246의 쌍둥이0개를 복원했습니다. 내용·상태·버전·OMR·이미지 참조와 생성 이력의 비교 범위도 보존됐습니다.

이 보고서는 로컬 근거만 읽어 새로 작성했습니다. 브라우저·네트워크·CMS·전역 원장/인덱스·기존 문서/맵을 조작하지 않았습니다. 실제로 검증한 것은 크기2의 단건 그룹 두 개를 병합한 한 사례입니다. 세트·단건 혼합, 모든 유형/단원/상태 조합과 서버 내부 그룹 구현까지 확인한 것은 아닙니다.

이하216·239·240·246은 각각 itemId2089216·2089239·2089240·2089246을 뜻합니다. A/B는 설명을 위한 표기이며 실제 DB 그룹ID가 아닙니다.

## 2. 첫 해제의 관찰 시간 초과와 독립 재조회

[3110](evidence/3110-own-twin-merge-unlink239-once.json)의 정상239 해제 뒤 기존 자동화 응답 리스너가 기대한 응답을 포착하지 못했습니다. action은 `Remove outcome unknown; never repeat`라는 관찰 오류를 기록합니다. 이 시점의 툴 오류만으로 CMS 해제 실패를 확정하지 않았으며 같은 해제를 재전송하지 않았습니다.

[3117](evidence/3117-own-twin-unlink239-independent-current-read.json)의 독립 GET은216과240이 서로2개 그룹을 이루고239는 그룹0개임을 확인합니다. [3118](evidence/3118-own-twin-unlink239-current-modal-state.json)의 실제 현재 모달도216·240만 표시하고 ownRemoveAttempted=true, 진행 중 요청 요소 없음으로 조회됐습니다. 따라서 업무85의 논리적 해제 결과는 이 후속 근거로 확인했습니다.

원래 해제 응답의 미수집 상태코드·본문을 GET 결과에서 역으로 만들어 기록하지 않았습니다. 시간 초과는 응답 관찰 문제로 분류하며, 실제 성공 판정과 재전송0회를 분리합니다.

## 3. COPY239/N의 생성 버튼과 계획 조정

[3123](evidence/3123-own239-independent-generation-controls.json)은 분리된239가 N·COPY/부모216·쌍둥이0개이고 생성 버튼 요소가 없음을 기록합니다. 버튼이 비활성이라는 결과와 버튼 자체가 없다는 결과를 구분했습니다.

이 표본은 N 상태와 COPY 생성 방식이 동시에 존재하므로 N 때문인지 생성 방식 때문인지, 또는 다른 조건 때문인지를 분리하지 못했습니다. N 문항은 모두 생성할 수 없다는 일반 규칙이나 서버 거절 정책으로 확대하지 않습니다. 생성 제어를 강제로 우회하거나 새 COPY를 만들지 않고, 이미 소유한 별도 단건246을 사용하도록 계획을 조정했습니다.

## 5. 다른 그룹 후보의 활성과 전체 합집합
