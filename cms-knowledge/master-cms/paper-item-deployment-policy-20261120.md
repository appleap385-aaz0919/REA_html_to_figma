# 문항·시험지 배포 및 평가지 상태 정책

2026-11-20 사용자 첨부와 후속 답변을 반영한 확정 정책입니다. 사용 중지와 미사용(N)의 관계, 폐기 문항의 검사 제외 범위, 자동 상태 변경의 적용 환경에 관한 세 질문은 모두 답변을 받았습니다. 기존 실제 CMS 조사 기록은 관찰 당시의 사실로 보존합니다.

## 상태 명칭과 문항 배포

**사용 중지와 미사용(N)은 같은 상태입니다.** 문항의 기존 ‘승인(미사용 N)’과 평가지의 ‘미사용(N)’에 대응하며, 사용 중지라는 별도 상태나 새 코드를 추가하지 않습니다. 사용은 기존 Y, 폐기는 D입니다.

문항은 **사용(Y) 상태일 때만 배포할 수 있습니다.** Draft(초안 R), 사용 중지·미사용(N), 폐기(D)는 배포할 수 없으며, 실패(F)를 포함한 그 밖의 비사용 상태도 허용하지 않습니다. 배포 버튼뿐 아니라 실제 배포 요청에서도 같은 자격을 검사해야 합니다.

## Master CMS의 시험지 상태 전환과 배포

1. 초안 시험지를 사용으로 바꾸려면 포함 문항이 모두 사용 상태여야 합니다. 초안이나 폐기 문항이 하나라도 있으면 전환할 수 없습니다. 아래의 배포 검사 제외 규칙을 이 상태 전환 검사에 적용하지 않습니다.
2. 시험지를 사용 처리한 뒤 문항이 폐기되면, 시험지 배포에서 해당 문항을 제외합니다. 사용 문항 9개와 폐기 문항 1개라면 9개만 배포합니다.
3. **폐기(D) 문항은 배포 대상, 선행 문항 배포 검사, Service DB 존재 검사에서 모두 제외합니다.** 한 번도 배포하지 않은 폐기 문항에도 선행 배포나 Service DB 레코드 존재를 요구하지 않습니다. 제외는 배포·검사 대상에서의 제외이며 원본 문항이나 시험지 편성을 삭제한다는 뜻은 아닙니다.
4. 사용 상태의 시험지를 배포할 때, 폐기 문항을 제외한 문항이 모두 Service에 선행 배포되어 있어야 합니다. 사용 중지·미사용(N) 문항이 포함되어 있으면 시험지를 배포할 수 없습니다. 개별 문항 배포는 위의 ‘사용(Y)만 허용’ 조건도 충족해야 합니다.

## Service의 시험지 승인과 대기중 → 초안 전환

1. 시험지를 승인 대기에서 승인으로 처리할 때 수정된 버전의 문항이나 미배포 문항이 포함되어 있으면 승인할 수 없습니다. 문항을 먼저 승인한 뒤 시험지를 승인할 수 있습니다.
2. 대기중인 평가지를 초안으로 전환하려면 검사 대상 문항이 모두 Service DB에 승인 수락 상태로 존재해야 합니다. 폐기 문항은 이 존재 검사에서도 제외합니다. 대상 문항 중 Service에서 반려된 문항이 있으면 전환할 수 없습니다.
3. 원본 첨부는 Service DB 존재 조건의 문항 상태로 초안·사용·폐기를 열거했습니다. 후속 답변에 따라 폐기는 검사 대상에서 제외하며, Service에 이미 존재하는 문항의 초안 상태와 Master에서 초안 문항을 새로 배포할 수 있는지는 구분합니다. Master 초안 문항의 신규 배포는 허용하지 않습니다.

Master 문항의 사용 상태, Service 배포 여부, Service 문항 승인, 시험지 승인은 서로 다른 조건입니다. 이 문서는 버전 비교 방식이나 Service 승인 상태의 내부 코드를 새로 정의하지 않습니다.

## Master CMS의 평가지 자동 상태 변경과 수동 복귀

다음 규칙은 **Master CMS에 적용합니다.** 이 규칙을 Service CMS의 자동 상태 변경으로 확대하지 않습니다.

| 상황 | 평가지 처리 |
|---|---|
| 사용 문항이 없고 모든 문항이 폐기 상태 | 자동으로 폐기(D) 처리합니다. |
| 사용 문항이 없고 사용 중지·미사용(N) 문항이 존재 | 자동으로 사용 중지·미사용(N) 처리합니다. 모든 문항이 N이어야 한다는 조건은 추가하지 않습니다. |
| 사용 중지 평가지의 문항이 이후 사용 상태로 복귀 | 평가지가 자동으로 사용 상태가 되지 않습니다. 관리자가 수동으로 변경해야 합니다. |
| 사용 중지 평가지의 승인 상태 복귀 시도 | 승인 문항이 1개 이상일 때 허용합니다. |

초안 → 사용의 ‘모든 문항이 사용’ 조건과 사용 중지 → 승인 복귀의 ‘승인 문항 1개 이상’ 조건은 출발 상태가 다른 별도 규칙입니다. 복귀할 수 있다는 조건만으로 선행 배포나 Service 승인 조건까지 충족했다고 판단하지 않습니다.

## 사용자 확인 결과

| 확인 항목 | 2026-11-20 사용자 답변에 따른 결정 |
|---|---|
| 사용 중지와 미사용(N)의 관계 | 같은 상태이며 새 상태를 추가하지 않습니다. |
| 폐기 문항의 검사 범위 | 배포 대상뿐 아니라 선행 배포와 Service DB 존재 검사에서도 제외합니다. |
| 자동 폐기·사용 중지·수동 복귀의 적용 환경 | Master CMS에 적용합니다. |

원본 첨부의 ‘사용 중지 상태 추가’ 표현은 기존 N과 같은 상태라는 후속 답변을 기준으로 해석합니다. 위 세 항목에 대한 확인 대기는 종료했으며, 검토 과정에서 확인한 정책 충돌은 이 답변으로 해소됐습니다.

- [구조화 정책 자료](../../design-specs/paper-item-deployment-policy-20261120.json): 확정 규칙, 상태 대응, 사용자 답변과 적용 환경을 기록합니다.

- 기존 평가지 R/Y/N/D 및 선행 문항 배포 조건: `design-specs/revision-aligned-plan.json`의 REV_PAP_LIST·REV_PAP_DETAIL·REV_PAP_EDIT입니다.

사용자가 이번 작업에 한해 중간 승인을 생략하고 HTML·Figma·Description 반영을 지시했습니다. HTML 목업에 배포 자격·대상별 선행 배포·폐기 제외·평가지 자동 상태 변경과 수동 복귀 조건을 적용했습니다. Figma는 기존 설명 8개와 기존 배포 팝업을 수정하고 상태 예시를 추가했으며 새 번호·Description 행은 추가하지 않았습니다. 기존 문항 상세의 상태 정보 설명은 08번 하나를 유지합니다.

HTML은 오프라인 Chrome에서 새 정책 검사 17개·기존 회귀 32개·패널 유지 8개·요청 흐름 11개, 총 68개가 통과했습니다. Figma는 실제 노드의 문구·번호·배치와 내보낸 화면 6개를 검수했습니다. [반영 및 검수 근거](../../design-specs/deployment-policy-sync-verification.json)에 범위를 기록했습니다.

실제 CMS·Service CMS 서버 구현·데이터 쓰기·실제 배포는 수행하지 않았습니다. Service의 승인·반려·버전 비교는 설계 Description에 반영한 정책이며 실제 Service 런타임을 검증한 결과가 아닙니다. 이번 승인 생략은 이 변경에만 적용하고 다음 HTML 요청은 기존 사용자 승인 절차를 따릅니다. HML 50문항 초과 평가지 등록 제한은 별도 정책으로 유지합니다.
